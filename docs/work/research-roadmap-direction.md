# Roadmap direction after 0.31.0

Status: awaiting the owner's decision · Researched: 2026-09-30 with the codex CLI (GPT, live web search, read-only checkout) · Ends as: a `ROADMAP.md` edit, backlog items, or a deletion

Question: Is the roadmap (Now F2–F6, Next M1–M4, Later, 1.0, non-goals) still pointed the right way, given the standards, protocols and tools that moved in the last 12–15 months?

The report below is the model's, unedited except that repository links are made relative. Its repository claims were spot-checked; its external claims carry their sources and were not independently re-verified.

### 1. Executive summary

- **Yes, the roadmap points in the right direction, but its order needs work.** Guardana should remain an offline-first verifier outside the production request path. Its strongest product claim is the combination of separate findings, unverified results, errors and coverage gaps with reproducible evidence, calibrated grading, pack locks and bounded cost—not the size of its attack library. Those behaviors are documented in [FEATURES.md](../../FEATURES.md) and [docs/product-status.md](../../docs/product-status.md).
- **Move testing of the user’s actual application ahead of output plugins and collector expansion.** Guardana’s agent harness tests a model using Guardana’s tools; the product status explicitly says it does not test the user’s agent. Live RAG retrieval is also absent. These are more consequential gaps than another renderer. [docs/product-status.md](../../docs/product-status.md)
- **Keep F2 and F3 first, then advance F5, F6, M2 and M4.** A quick custom check, typed access to failed runs, regrading and a reproducible application run form a useful path from one finding to a durable release gate. [ROADMAP.md](../../ROADMAP.md)
- **Treat F4 as a smaller deliverable.** JSON, JUnit and SARIF already ship in Guardana; GitHub accepts SARIF 2.1.0, and ModelAudit also exports it. A safe webhook may help teams, but a general output-plugin ecosystem has weak evidence of demand before the two-team F6 trial. [FEATURES.md](../../FEATURES.md), [GitHub SARIF documentation](https://docs.github.com/en/code-security/concepts/code-scanning/sarif-files), [ModelAudit documentation](https://www.promptfoo.dev/docs/model-audit/usage/)
- **Do not sell “unknown is not pass” as wholly unique.** PyRIT added undetermined scores, and Inspect distinguishes unscored samples. Guardana’s stronger distinction is carrying missingness through planning, gates, saved runs, comparisons and exports together. [PyRIT v1.1.0](https://github.com/microsoft/PyRIT/releases/tag/v1.1.0), [Inspect scoring reference](https://inspect.aisi.org.uk/reference/inspect_score.html), [FEATURES.md](../../FEATURES.md)
- **The 2026 protocol work is partly done already.** Guardana documents negotiation of both MCP `2025-11-25` and `2026-07-28`, including sessionless behavior. The priority is conformance against real implementations and new task, authorization and registry edge cases; do not schedule a duplicate basic MCP transport project. [docs/usage-probe.md](../../docs/usage-probe.md), [MCP 2026 release](https://blog.modelcontextprotocol.io/posts/2026-07-28/)
- **Preserve the Guardana–Control boundary.** Runtime enforcement, live intake and agent fleet supervision have well-funded competitors and are assigned to the separate Control project. Guardana’s opportunity is a credible pre-release and recorded-evidence gate that can operate without them. [docs/design/guardana-and-control.md](../../docs/design/guardana-and-control.md)

### 2. What changed in the landscape

**Standards and frameworks**

- **OWASP LLM Top 10.** The 2025 edition was released **2024-11-18**, before this review window. The 2026 edition was listed **2026-08-03** and announced **2026-09-02**; its PDF still contains a publication-date placeholder, so the PDF’s exact publication date is **unverified**. Excessive Agency rose to LLM03, Unbounded Consumption to LLM06, and Prompt Injection explicitly includes image and audio carriers. Guardana already maps rules to both editions, but its status page says it tests text only. [OWASP 2026 guide](https://genai.owasp.org/download/56857/?tmstv=1785822482), [OWASP announcement](https://genai.owasp.org/2026/09/01/owasp-genai-security-project-unveils-2026-top-10-for-llm-applications-new-agent-control-standard-and-sponsors-as-community-tops-30000-members/), [Guardana rule catalog](../../docs/generated/rule-catalog.md), [product status](../../docs/product-status.md)
- **OWASP agentic guidance.** The Top 10 for Agentic Applications appeared **2025-12-09**. It makes tool misuse, privilege abuse, supply chain compromise, memory poisoning, inter-agent communication and cascading failures explicit review units. Guardana maps built-ins to eight ASI entries; its generated coverage lists no ASI08 or ASI10 mapping. A mapping is evidence of relevance, not proof that a category is fully tested. [OWASP Agentic Top 10](https://genai.owasp.org/resource/owasp-top-10-for-agentic-applications-for-2026/), [Guardana taxonomy coverage](../../docs/generated/taxonomy-coverage.md)
- **OWASP testing method.** The AI Testing Guide v1 was published **2025-11-26** as a broader, technology-neutral trustworthiness testing method. That supports application-owned quality criteria without forcing each one into a security taxonomy, as Guardana’s roadmap proposes. [OWASP AI Testing Guide](https://owasp.org/projects/ai-testing-guide), [ROADMAP.md](../../ROADMAP.md)
- **MITRE ATLAS.** ATLAS v5.5.0 added AI Agent Tool Poisoning and related supply chain techniques in **2026-03**; v5.6.0 followed **2026-05-04**. Monthly content releases then separated content version from data-format version; **v2026.07** split tool poisoning into definition, implementation and runtime-response techniques, and **v2026.08** added autonomous agent communication and authority-expansion mitigations. **v2026.09** was released **2026-09-15**. Guardana’s README names v5.6.0, so taxonomy maintenance and provenance are behind the content stream. [ATLAS releases](https://github.com/mitre-atlas/atlas-data/releases), [README.md](../../README.md)
- **NIST.** AI 100-2e2025 was final in **2025-03**, outside the review window; it supplies adversarial-ML terminology, not a certification checklist. AI 600-1 was published **2024-07-26**, also outside the window. NIST says AI RMF 1.0 is being revised and published a critical-infrastructure profile concept note **2026-04-07**. Guardana should version crosswalks and record evidence, rather than imply that a rule hit satisfies an RMF outcome. [NIST AI 100-2e2025](https://csrc.nist.gov/pubs/ai/100/2/e2025/final), [NIST AI 600-1](https://www.nist.gov/publications/artificial-intelligence-risk-management-framework-generative-artificial-intelligence), [NIST AI RMF page](https://www.nist.gov/itl/ai-risk-management-framework)
- **EU AI Act.** Obligations for *providers of general-purpose AI models* began **2025-08-02**; the voluntary GPAI Code of Practice was published **2025-07-10**, and the Commission’s enforcement powers began **2026-08-02**. Technical documentation, training-content summaries and, for systemic-risk models, risk management and cybersecurity make traceable test evidence useful. They do not make Guardana a compliance certifier or mean every Guardana user is a GPAI provider. [Commission obligations](https://digital-strategy.ec.europa.eu/en/factpages/general-purpose-ai-obligations-under-ai-act), [Code of Practice](https://digital-strategy.ec.europa.eu/en/policies/contents-code-gpai), [Commission guidelines](https://digital-strategy.ec.europa.eu/en/policies/guidelines-gpai-providers)
- **ISO/IEC 42001.** The AI management-system standard dates to **2023-12**; ISO/IEC 42006, published in **2025**, specifies requirements for bodies auditing and certifying those systems. This strengthens demand for records of scope, method, results and exceptions. A precise 2025–2026 adoption or certificate count was **unverified** from the primary sources reviewed; Guardana should not claim one. [ISO/IEC 42001](https://www.iso.org/standard/42001), [ISO/IEC 42006](https://www.iso.org/standard/42006), [ISO Survey method](https://committee.iso.org/es/sites/isoorg/home/standards/committee-for-conformity-assessm/resources-for-casco/the-iso-survey.html)

**Protocols, telemetry and artifacts**

- **MCP changed twice.** The **2025-11-25** revision added task workflows, URL-mode elicitation and authorization extensions. The stable **2026-07-28** revision removed protocol-level sessions and the initialization handshake, introduced `server/discover`, changed routing and cache semantics, hardened issuer and credential handling, and moved Tasks into an extension. The official registry launched in preview **2025-09-08** and froze its v0.1 API **2025-10-24**. Guardana already handles the two current protocol revisions, but a server manifest pin does not establish the integrity of the package or process behind that manifest. [MCP November release](https://blog.modelcontextprotocol.io/posts/2025-11-25-first-mcp-anniversary/), [MCP July release](https://blog.modelcontextprotocol.io/posts/2026-07-28/), [registry](https://github.com/modelcontextprotocol/registry), [Guardana MCP guide](../../docs/usage-probe.md)
- **A2A became a concrete protocol target.** A2A v1.0.0 shipped **2026-03-12**, with task listing, authentication changes and breaking wire changes from v0.3.0. It is now specific enough for a narrow agent-card, identity, task-visibility and handoff test fixture. A broad multi-agent attack platform remains premature. [A2A v1.0.0](https://github.com/a2aproject/A2A/releases/tag/v1.0.0), [A2A v1 changes](https://github.com/a2aproject/A2A/blob/main/docs/whats-new-v1.md)
- **OpenTelemetry GenAI conventions remain moving input.** The general semantic-conventions repository moved GenAI material to a dedicated repository in **2026-06**; the GenAI conventions still label their spans **Development**. Guardana is right to normalize a declared input revision into its own versioned evidence format, with fixtures for absent or redacted content. [OpenTelemetry v1.42.0 release](https://github.com/open-telemetry/semantic-conventions/releases), [GenAI convention status](https://github.com/open-telemetry/semantic-conventions-genai/blob/main/docs/gen-ai/README.md), [ROADMAP.md](../../ROADMAP.md)
- **SARIF and model-file scanning are established plumbing.** GitHub supports a subset of SARIF 2.1.0 for code scanning. Promptfoo released open-source ModelAudit **2026-03-10**, reporting coverage of pickle, safetensors, GGUF, ONNX and Keras among many formats, plus SARIF and SBOM output. Its format-count and false-positive claims are vendor-reported; independent comparative validation is **unverified**. Pickle permits execution on load; safetensors avoids executable serialization but does not authenticate provenance; GGUF metadata, ONNX external data and Keras custom or lambda loading still need format-specific checks. Guardana should maintain high-value fixtures and honest unreadable-file outcomes, rather than compete on format count. [GitHub SARIF](https://docs.github.com/en/code-security/concepts/code-scanning/sarif-files), [ModelAudit launch](https://www.promptfoo.dev/blog/open-sourcing-modelaudit/), [Hugging Face pickle guidance](https://huggingface.co/docs/hub/security-pickle), [GGUF format](https://huggingface.co/docs/hub/gguf), [Keras loading API](https://keras.io/api/models/model_saving_apis/model_saving_and_loading/)

### 4. Missing from the roadmap

1. **A versioned protocol conformance programme.** Name supported MCP revisions, registry metadata and authorization cases in a fixture matrix; add a narrow A2A v1 path. The current MCP guide is unusually precise, but the roadmap lacks an ongoing interoperability gate against independent servers. [Guardana MCP guide](../../docs/usage-probe.md), [MCP 2026 release](https://blog.modelcontextprotocol.io/posts/2026-07-28/), [A2A v1.0.0](https://github.com/a2aproject/A2A/releases/tag/v1.0.0)
2. **A real-application security recipe with controlled side effects.** Require safe doubles or staging fixtures for the user’s agent, including tool arguments, retrieval, tenant identity, approvals and handoffs. A model harness result must never be presented as proof about an application it did not execute. [product status](../../docs/product-status.md), [Guardana–Control design](../../docs/design/guardana-and-control.md)
3. **RAG data-boundary and carrier tests.** Add one live retriever adapter and fixtures for document poisoning and cross-tenant retrieval; select a PDF or image carrier with a pilot team. Today those failures are either trace-only, scripted or outside text coverage. [product status](../../docs/product-status.md), [OWASP 2026 guide](https://genai.owasp.org/download/56857/?tmstv=1785822482)
4. **Agent supply-chain provenance beyond a tool-description hash.** Record the approved tool schema, package or image identity, resolved server origin, agent skill/configuration identity and changes between approval and execution. ATLAS’s newer poisoned-artifact and tool-implementation cases explain why a stable manifest can be insufficient. [ATLAS releases](https://github.com/mitre-atlas/atlas-data/releases), [Cisco scanner projects](https://github.com/cisco-ai-defense), [Guardana MCP guide](../../docs/usage-probe.md)
5. **A maintained evidence-quality contract for imported runs.** Specify source trust, missing fields, redaction, sampling, judge identity and comparability for garak, promptfoo, Inspect and OpenTelemetry inputs. Guardana already imports external observations as unverified; the roadmap should say when and how a team can turn one into a verified local regression. [README.md](../../README.md), [OpenTelemetry GenAI status](https://github.com/open-telemetry/semantic-conventions-genai/blob/main/docs/gen-ai/README.md)
6. **Published detection limits.** For each rule family, distinguish a tested exploit or invariant from a heuristic lead and from a framework mapping. The generated taxonomy page explicitly says entry coverage is not full coverage; the promised per-category assessment is not present in the roadmap text reviewed. [taxonomy coverage](../../docs/generated/taxonomy-coverage.md), [ROADMAP.md](../../ROADMAP.md)

### 5. Risks to the plan

- **A first-run trust contradiction.** Entry-point packs are installed Python code and `--plugins all` remains the default. A no-account offline starter can still import code the user did not mean to trust. Make built-ins the default for the starter, show exactly what a pack can execute, and advance non-executing packs. [product status](../../docs/product-status.md)
- **False assurance from breadth.** “51 checks” and multiple taxonomy badges can be read as comprehensive coverage. Guardana itself says the agent harness is its own, RAG coverage is partial, and multimodal inputs are absent. Lead reports with tested surface, required evidence and omitted dimensions. [README.md](../../README.md), [product status](../../docs/product-status.md)
- **A denial-of-service path in a user-defined check.** The 0.30.0 changelog says a regex over a bounded reply can still backtrack for a very long time and hang. This is a concrete execution-budget gap, especially before advertising arbitrary private checks as safe to run in CI. [CHANGELOG.md](../../CHANGELOG.md)
- **Statistics before representative data.** Paired tests cannot rescue a model-only harness that missed the real application, or a judge calibration that is stale after a model change. The roadmap should make application coverage, assessor identity and calibration currency prerequisites to a regression claim. [product status](../../docs/product-status.md), [ROADMAP.md](../../ROADMAP.md)
- **Platform work outrunning adoption evidence.** Output plugins, collector trends, central policy distribution and SSO each create support and migration obligations. F2’s five users and F6’s two independent teams are the appropriate evidence gates before enlarging those commitments. [ROADMAP.md](../../ROADMAP.md), [framework audit](../../docs/design/framework-usability-audit.md)
