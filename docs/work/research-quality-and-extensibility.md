Question: Does Guardana still meet the highest bar for engineering quality and extensibility, compared with garak, PyRIT, promptfoo, Inspect AI and DeepEval?

### 1. Verdict

Guardana’s engine has strong, reviewable extension contracts and generally keeps incomplete checks separate from successful verdicts ([registry.py:20](../../packages/guardana-core/src/guardana/core/registry.py), [gate.py:69](../../packages/guardana-core/src/guardana/core/gate.py)). **The highest end-to-end bar is not yet met:** a stopped run can look clean in JUnit, and a trace field presented as a document digest does not hash the document’s contents ([junit.py:113](../../packages/guardana-report/src/guardana/report/junit.py), [load.py:313](../../packages/guardana-core/src/guardana/core/trace/load.py)). Extensibility is credible for rules, evaluators, targets and taxonomies, but output plugins and a supported Python result workflow remain unreleased ([registry.py:269](../../packages/guardana-core/src/guardana/core/registry.py), [product-status.md:35](../../docs/product-status.md)). This reviews the supplied, modified checkout; its 0.31.0 changelog is dated September 30, one day after the requested review date, and publication of that release is **not verified** ([CHANGELOG.md:10](../../CHANGELOG.md)).

### 2. Strengths

- **Extension discovery has enforceable boundaries.** Four entry-point groups load taxonomies before rules; conflicting IDs and reserved target schemes are rejected, while a failed entry point is recorded without discarding the other plugins ([registry.py:20](../../packages/guardana-core/src/guardana/core/registry.py), [registry.py:99](../../packages/guardana-core/src/guardana/core/registry.py), [registry.py:269](../../packages/guardana-core/src/guardana/core/registry.py)). The installable example exercises all four groups and declares them in its pack manifest ([examples/custom_rule/pyproject.toml:11](../../examples/custom_rule/pyproject.toml), [guardana-pack.yaml:32](../../examples/custom_rule/src/acme_rules/guardana-pack.yaml)).
- **The engine records why it could not conclude.** The runner retains findings produced before an error or budget stop, routes unreadable artifacts to `errors`, and keeps inconclusive findings separate; the gate makes stops and demanded coverage shortfalls indeterminate ([runner.py:165](../../packages/guardana-core/src/guardana/core/runner.py), [runner.py:185](../../packages/guardana-core/src/guardana/core/runner.py), [gate.py:69](../../packages/guardana-core/src/guardana/core/gate.py), [gate.py:105](../../packages/guardana-core/src/guardana/core/gate.py)). Judge-graded suites decline without usable calibration ([product-status.md:33](../../docs/product-status.md)).
- **Cost and architecture have executable gates.** Tests count file parses, tree walks and probe requests rather than relying only on timing; CI runs strict mypy, import contracts, branch coverage and critical-area floors ([test_scan_cost.py:60](../../packages/guardana-rules/tests/test_scan_cost.py), [test_probe_cost.py:183](../../packages/guardana-rules/tests/test_probe_cost.py), [ci.yml:75](../../.github/workflows/ci.yml), [critical_coverage.py:22](../../scripts/critical_coverage.py)). Import-linter explicitly forbids a dependency from the engine or CLI on the optional collector ([pyproject.toml:251](../../pyproject.toml)).
- **Release controls address real installation risks.** CI installs the example pack in isolation, the release script waits for CI on the exact release commit before pushing its tag, and the publish workflow creates build provenance attestations ([ci.yml:190](../../.github/workflows/ci.yml), [release.py:168](../../scripts/release.py), [release.yml:65](../../.github/workflows/release.yml)). Successful execution of those controls for 0.31.0 is **not verified**.

### 3. Weaknesses and risks

1. **Critical — JUnit can present a budget-stopped run as clean.** The gate marks any stop indeterminate, but `JUnitRenderer` never reads `stopped_by`; with completed rules and no findings, its XML can contain no error or failure even though the run stopped ([gate.py:69](../../packages/guardana-core/src/guardana/core/gate.py), [junit.py:13](../../packages/guardana-report/src/guardana/report/junit.py), [junit.py:113](../../packages/guardana-report/src/guardana/report/junit.py)). A team relying on the JUnit artifact rather than the process exit can accept partial verification. **Fix:** emit a run-level `<error>` for every stop, derive the `tests` count from emitted cases, and test budget and interrupt states across every renderer.
2. **High — trace provenance does not identify trace contents.** `Provenance.document_digest` says it covers bytes read, but `read_trace` hashes only the file’s basename and size; different same-named, same-sized traces receive the same value ([model.py:74](../../packages/guardana-core/src/guardana/core/trace/model.py), [load.py:85](../../packages/guardana-core/src/guardana/core/trace/load.py), [load.py:313](../../packages/guardana-core/src/guardana/core/trace/load.py)). That weakens an adopter’s ability to tie an audit claim to the evidence reviewed. **Fix:** hash bytes while streaming the bounded read, version the digest interpretation, and test equal-size content changes.
3. **High — built-in fixture proof is incomplete.** Only 12 built-in rules are pinned as having finding, clean and inconclusive fixtures, against 51 advertised checks; the repository’s own test calls the remaining migration unfinished ([test_builtin_fixture_coverage.py:1](../../packages/guardana-rules/tests/test_builtin_fixture_coverage.py), [test_builtin_fixture_coverage.py:24](../../packages/guardana-rules/tests/test_builtin_fixture_coverage.py), [README.md:23](../../README.md)). A team cannot infer that every built-in has demonstrated its refusal to give a verdict on unreadable input. **Fix:** complete the three-outcome fixtures and require them for each newly shipped rule.
4. **High — a partly unverified run may still exit successfully by default.** `fail_on_inconclusive` and `fail_on_skipped` default to false; a gate test explicitly confirms a pass when one rule concludes and another is unverified ([profile/model.py:13](../../packages/guardana-core/src/guardana/core/profile/model.py), [test_gate_outcome.py:62](../../packages/guardana-core/tests/test_gate_outcome.py)). Reports expose that uncertainty, but a team using only exit status may miss lost coverage. **Fix:** provide a clearly named strict CI policy that requires selected rules and rejects their skips or inconclusive results, while preserving the current general-purpose policy as an explicit choice.
5. **Medium — output extension stops at protocols.** `Renderer` and `Reporter` interfaces exist, but CLI formats are a closed four-value enum, and renderer/reporter plugins are listed as unreleased ([base.py:7](../../packages/guardana-report/src/guardana/report/base.py), [_formats.py:4](../../packages/guardana-cli/src/guardana/cli/_formats.py), [product-status.md:35](../../docs/product-status.md)). An adopting team needs a Guardana CLI change to add its own output destination. **Fix:** implement the proposed discovery, redaction and collision checks, then prove an independently installed renderer and reporter work end to end ([output-plugins.md:22](../../docs/design/output-plugins.md)).
6. **Medium — documentation and adoption limits need tighter checks.** The rule guide says `RuleLoadError` becomes a skip, whereas the runner catches it as an error; the architecture guide’s target enum omits the implemented `TRACE` kind ([writing-rules.md:501](../../docs/writing-rules.md), [runner.py:305](../../packages/guardana-core/src/guardana/core/runner.py), [architecture.md:55](../../docs/architecture.md), [target/base.py:20](../../packages/guardana-core/src/guardana/core/target/base.py)). Extension authors can build against the wrong failure contract. **Fix:** correct both pages and add contract examples that execute against current code. Separately, judge calibration can become stale after a model change without detection; require judge identity and calibration freshness where a probabilistic verdict gates deployment ([product-status.md:104](../../docs/product-status.md)).

### 5. Gaps in the quality process

- Generated-doc, site, `llms.txt` and sitemap checks are in the local gate, but no corresponding steps appear in the GitHub CI workflow reviewed; a contributor who relies on CI alone may miss stale generated output ([ci_local.sh:108](../../scripts/ci_local.sh), [ci.yml:83](../../.github/workflows/ci.yml), [ci.yml:157](../../.github/workflows/ci.yml)).
- The 90% aggregate and critical-area coverage floors protect exercised lines, but they did not establish cross-renderer agreement on a stopped run; the stopped-run renderer tests exercise human output only ([pyproject.toml:227](../../pyproject.toml), [critical_coverage.py:22](../../scripts/critical_coverage.py), [test_stopped_run_rendering.py:29](../../packages/guardana-report/tests/test_stopped_run_rendering.py)).
- Rule fixture coverage remains a ratchet at 12 rather than a completed acceptance gate ([test_builtin_fixture_coverage.py:24](../../packages/guardana-rules/tests/test_builtin_fixture_coverage.py)). Provider conformance is also explicitly untested, so a capability handshake is not yet evidence of behavior across named providers ([product-status.md:91](../../docs/product-status.md)).
- Tests and CI were **not run** for this review under the read-only restriction. Live CI results, PyPI publication and actual attestation verification for 0.31.0 are **not verified**; the repository establishes configured workflows, not their successful execution ([ci.yml:1](../../.github/workflows/ci.yml), [release.yml:65](../../.github/workflows/release.yml)).

1. **S — Fix JUnit’s stopped-run representation** and add a shared result-state matrix across human, JSON, SARIF and JUnit ([junit.py:113](../../packages/guardana-report/src/guardana/report/junit.py), [gate.py:69](../../packages/guardana-core/src/guardana/core/gate.py)).
2. **M — Make trace provenance a content digest**, version its meaning and test same-name, same-size different contents ([load.py:313](../../packages/guardana-core/src/guardana/core/trace/load.py), [model.py:74](../../packages/guardana-core/src/guardana/core/trace/model.py)).
3. **L — Finish three-outcome fixtures for built-ins and provide a strict, selected-coverage CI policy** so incomplete checks cannot be mistaken for assurance from exit status alone ([test_builtin_fixture_coverage.py:24](../../packages/guardana-rules/tests/test_builtin_fixture_coverage.py), [profile/model.py:13](../../packages/guardana-core/src/guardana/core/profile/model.py)).
4. **M — Put generated-documentation checks in GitHub CI** and pin executable examples for the published extension and error contracts ([ci_local.sh:108](../../scripts/ci_local.sh), [writing-rules.md:501](../../docs/writing-rules.md)).
5. **L — Ship independently installed output plugins and the supported Python result facade**, with compatibility and redaction tests before advertising them as general extension points ([product-status.md:35](../../docs/product-status.md), [output-plugins.md:55](../../docs/design/output-plugins.md)).
